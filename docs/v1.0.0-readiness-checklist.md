# ResolveHub v1.0.0 Readiness Checklist

Use this checklist before tagging a portfolio release.

## Product Scope

- [x] Organization multi-tenancy enforced in backend ticket/user access.
- [x] Role-based access rules implemented for `CUSTOMER`, `AGENT`, `MANAGER`, `ADMIN`.
- [x] Ticket lifecycle includes creation, comments, status workflow, assignment, SLA/overdue, and audit logs.
- [x] AI workflow includes suggestion endpoint and manual apply endpoint (no auto-apply).
- [x] Ticket list supports search and filtering (status, priority, category, overdue).

## Backend Release Checks

- [ ] `cd backend && ./mvnw clean verify`
- [ ] Swagger UI loads in dev profile (`/swagger-ui.html`).
- [ ] Demo credentials authenticate in local dev profile.
- [ ] Cross-organization access attempts are rejected.

## Frontend Release Checks

- [ ] `cd frontend && npm test -- --run`
- [ ] `cd frontend && npm run build`
- [ ] Login, ticket list filters, detail workflow, assignment, audit log, and AI apply flow all smoke-tested.

## Documentation and Demo Assets

- [x] README feature list and CI description match implementation.
- [x] Screenshot paths in README resolve to existing files under `docs/images`.
- [x] Deployment and AI provider docs reflect current environment variable names.
- [ ] Record a short demo walkthrough video (optional but recommended for portfolio review).

## CI and Container Validation

- [x] GitHub Actions validates backend tests, frontend test/build, and Docker image builds.
- [ ] `docker compose --profile app up --build` smoke-tested locally.

## Release Packaging

- [ ] Final pass on README clarity and grammar.
- [ ] Confirm no sensitive values/secrets are committed.
- [ ] Tag release as `v1.0.0` after all unchecked items are complete.
